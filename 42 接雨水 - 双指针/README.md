# 42. 接雨水

| 项 | 内容 |
| --- | --- |
| 来源 | [leetcode.cn/problems/trapping-rain-water](https://leetcode.cn/problems/trapping-rain-water) |

| 本次解法 | 双指针（从两端向中间收） |
| 时间 / 空间 | `O(n)` / `O(1)` |
| 记录时间 | 2026-11-06 |

## 1. 题意

给定 `n` 个非负整数表示每个宽度为 `1` 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。

### 示例 1

```
输入：height = [0,1,0,2,1,0,1,3,2,1,2,1]
输出：6
解释：可以接 6 个单位的雨水。
```

### 示例 2

```
输入：height = [4,2,0,3,2,5]
输出：9
```

### 提示

- `n == height.length`
- `1 <= n <= 2 * 10^4`
- `0 <= height[i] <= 10^5`

## 2. 思路：双指针

**先看单列。** 第 `i` 列能存多少水，等于它左右两侧最高柱子中**较矮**的那一根，减去它自己的高度：

```
water[i] = min(max(height[0..i]), max(height[i..n-1])) - height[i]
```

这就是「短板效应」：水面高度由矮的那堵墙决定，再高的墙也没用。

**再看怎么省掉两遍扫描。** 直接照公式算，需要每列左右两侧的最大值，要么预处理两个数组（`O(n)` 空间），要么每次重扫（`O(n²)` 时间）。

双指针的关键一步在这里：设 `l`、`r` 分别指向两端，`maxl` 是 `l` 左边见过的最高柱子，`maxr` 是 `r` 右边见过的最高柱子。

- 若 `height[l] < height[r]`：左列矮。它右边**至少**有一根不低于它的柱子（就是 `height[r]`，而 `r` 右侧的最高只会更高），所以左列的水面上限已经被 `maxl` 完全决定，**可以立刻结算**，不必管右边到底多高。
- 否则右列矮，对称地立刻结算右列。

这就是为什么只需要 `O(1)` 空间：任何时刻我们都只结算「天花板已经确定」的那一侧。

### 为什么最后那一列不用算

指针相遇的位置 `l == r`，一定是**全局最高的柱子**。因为每次都是矮的一侧先动，站在全局最高柱子上的那个指针永远不会被移走（另一侧永远比它矮，条件 `height[l] < height[r]` 不成立），所以另一侧会一路走到它身上。

最高柱子自身存不住水，所以循环在 `l == r` 时停下是正确的，不是漏算。

## 3. 手动推演（示例 1）

`height = [0,1,0,2,1,0,1,3,2,1,2,1]`，初始 `l = 0`、`r = 11`、`maxl = maxr = 0`、`res = 0`。

| 步 | l | r | 比较 | 结算列 | maxl | maxr | 本列积水 | res |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 11 | `0 < 1` 左矮 | 0 | 0 | 0 | `0 - 0 = 0` | 0 |
| 2 | 1 | 11 | `1 < 1` 否 | 11 | 0 | 1 | `1 - 1 = 0` | 0 |
| 3 | 1 | 10 | `1 < 2` 左矮 | 1 | 1 | 1 | `1 - 1 = 0` | 0 |
| 4 | 2 | 10 | `0 < 2` 左矮 | 2 | 1 | 1 | `1 - 0 = 1` | 1 |
| 5 | 3 | 10 | `2 < 2` 否 | 10 | 1 | 2 | `2 - 2 = 0` | 1 |
| 6 | 3 | 9 | `2 < 1` 否 | 9 | 1 | 2 | `2 - 1 = 1` | 2 |
| 7 | 3 | 8 | `2 < 2` 否 | 8 | 1 | 2 | `2 - 2 = 0` | 2 |
| 8 | 3 | 7 | `2 < 3` 左矮 | 3 | 2 | 2 | `2 - 2 = 0` | 2 |
| 9 | 4 | 7 | `1 < 3` 左矮 | 4 | 2 | 2 | `2 - 1 = 1` | 3 |
| 10 | 5 | 7 | `0 < 3` 左矮 | 5 | 2 | 2 | `2 - 0 = 2` | 5 |
| 11 | 6 | 7 | `1 < 3` 左矮 | 6 | 2 | 2 | `2 - 1 = 1` | 6 |

第 11 步之后 `l` 右移到 7，与 `r` 相等，循环结束。下标 7 是全局最高的柱子（高度 3），积水必为 0，不需要再算。合计 **6**。

## 4. 代码

```cpp
class Solution {
public:
    int trap(vector<int>& height) {
        int res = 0;
        int n = height.size();
        int l = 0;
        int r = n - 1;
        int maxl = 0;
        int maxr = 0;
        while (l < r) {
            if (height[l] < height[r]) {
                maxl = max(height[l], maxl);
                res += maxl - height[l];
                l++;
            }
            else {
                maxr = max(height[r], maxr);
                res += maxr - height[r];
                r--;
            }
        }
        return res;
    }
};
```

## 5. 边界与易错点

1. **顺序不能反**：必须**先用当前柱高更新 `maxl`，再用 `maxl - height[l]` 算水量**。如果先加 `maxl - height[l]` 再更新，第一根柱子会拿到负值或漏掉本次的抬升。
2. **`<` 与 `<=`**：条件写 `height[l] < height[r]`，相等时走 `else` 结算右侧。写成 `<=` 也正确，只是结算方向反过来。**两种都行，但两边的分支必须自洽**——别一处更新 `maxl` 一处更新 `maxr`。
3. **相遇列不计入**是正确的（见 §2 末尾），不要为了「算全所有列」而把循环条件改成 `l <= r`，那会重复计算或越界。
4. **`n < 2` 的输入**：`n == 1` 或空数组接不住水，直接返回 0。本题约束是 `n >= 1`，但写通用的解法时值得补上。
5. **柱高为 0 的位置不是「没水」**：高度 0 的列照样能积水（示例 1 的下标 2 和 5），靠的是两侧的墙。
6. **别写成「找最高点左右两侧分别扫」**：那样也对，但要两遍扫描；本题双指针一遍就能出结果。
