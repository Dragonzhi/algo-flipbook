# DESIGN.md — 接雨水 · 演示页

> 色板沿用工作区模板（力扣浅色：白底 + 发丝线 + 黑灰黄），语义色只改指向本题含义。
> 模板来源与取舍理由见 §1 与根目录 `AGENTS.md`。

## 1. 为什么这套方向

演示页要在一屏里同时容纳数组舞台、指针、变量表和代码高亮。方向定成**力扣（leetcode.cn）题解页的骨架**：
白底 + 发丝线 + 深灰文字 + 单一橙色强调，信息密度高，不要装饰。

选择理由：这页是刷题笔记里的插图，长期和 leetcode.cn 并排看——浅色页面并排不刺眼，截图贴进笔记也和
官方题解同源。橙色只表示「可交互 / 当前焦点」，取代了深色版里「绿 = 已就位」的装饰性用法。

`--design-system`（query: *algorithm learning tool code visualizer light editorial*）返回的仍是
Dark Mode (OLED) + landing page 版式，与「浅色、单页工具」冲突，**不采用**。令牌直接取自 leetcode.cn
线上 CSS 变量（light-gray / light-green / light-blue / light-purple 色阶）与 --brand-orange，再按
WCAG 降档到可用的文字色。

## 2. 色板（全部登记，新代码不得新增十六进制）

| 角色 | Token | 值 | 实测对比度 |
| --- | --- | --- | --- |
| 页面底色 | `--bg` | `#FFFFFF` | — |
| 卡片 / 面板 | `--panel` | `#FFFFFF` | — |
| 内凹面（读数格、解说、速度分段器、代码区） | `--well` / `--code-bg` | `#F5F5F5` / `#FAFAFA` | — |
| 进度条轨道 | `--well-2` | `#F0F0F0` | 装饰性 |

| 发丝线 | `--line` | `#DFDFDF` | 装饰性（浅色下靠描边分层，不靠亮度） |
| 控件描边 | `--line-strong` | `#B7B7B7` | 装饰性 |
| 橙：品牌 / 学习进度（进度条、中等难度） | `--amber` | `#FFA116` | 填充色，不做小字 |

| A 语义 | `--tone-a` | 题目给，本页 `#008024` | 5.11:1 on 白 / 4.84:1 on 浅绿底 |
| B 语义 | `--tone-b` | 题目给，本页 `#005BDA` | 5.98:1 on 白 / 5.47:1 on 浅蓝底 |
| 难度徽标：简单 | `.chip-diff[data-diff="简单"]` | `#0E7B7B` on `#E8FFFB` | 4.86:1 |
| 难度徽标：中等 | `.chip-diff[data-diff="中等"]` | `#8A5300` on `#FFF7E0` | 5.92:1 |
| 难度徽标：困难 | `.chip-diff[data-diff="困难"]` | `#A1121B` on `#FFECE8` | 7.6:1 |

测量方式：WCAG 相对亮度公式逐对计算（sRGB → 线性化 → (L1+0.05)/(L2+0.05)），不是估值。

**力扣的品牌色不能直接当文字色**：`#01B328` → 2.81:1、`#1CB8B8` → 2.44:1、`#FFB800` → 1.73:1、
`#FFA116` → 2.03:1，都不达 4.5:1。所以语义色一律取同色阶 `-80` 深档；橙只做填充（按钮、进度、
tab 下划线、当前行），不做小字。

**语义分工**：绿 = 主操作（播放）；橙 = 品牌与学习进度（进度条、中等难度）；A / B 只出现在数据上。
「正在执行」不用彩色：代码当前行是**中性灰底 + 2px 墨线**，本步写入的格子是**2px 墨色描边**，
变化过的读数在左侧压一条墨线。黄色一旦用来标状态，就会被读成警告。

## 3. 字体

- 正文：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans SC", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif`
- 代码与数字：`"Cascadia Mono", "Cascadia Code", "JetBrains Mono", Consolas, "SF Mono", monospace`

**降级说明**：不引入 webfont（离线单页），全部走系统栈。Windows 上 Segoe UI Variable（拉丁）
+ Noto Sans SC（中文）已经足够稳；等宽用 Cascadia **Mono** 而不是 Cascadia Code——后者会把
`>=` 渲染成 `≥` 连字，在代码演示里是误读源。字体缺失按栈回退，不出现方框。

字阶：11 / 12 / 13 / 13.5 / 15 / 17 / 20 / 28（px）；正文行高 1.62，代码行高 1.72；
数字统一 `font-variant-numeric: tabular-nums`，步进时宽度不跳。

## 5. 动效

| 项 | 值 |
| --- | --- |
| 时长 | UI 反馈 160ms；指针移动 240ms |
| 缓动 | `cubic-bezier(0.22, 0.9, 0.3, 1)` |
| 库 | motion（14.9.1，UMD 本地内置 `../assets/motion.min.js`）；缺失时回退 Web Animations API |
| 降级 | `prefers-reduced-motion: reduce` 时全部改为 0ms 直切，**信息不丢** |

本题**不使用搬运动效**（`move`）：接雨水没有「把一个值搬到另一格」的动作，硬加飞行块
只会是装饰。状态变化由「格子染上语义色 + 指针移动 + 下行浮出数字」三件事承载。

## 5c. 版面结构

- 一张卡装完主要信息：示例 tab → 图例 → **2D 柱状图（SVG）** → 读数 → 当前分支 → 解说 → 进度条 → 重置与速度。
- 柱状图由 `assets/demo.js` 的 `layout: "bars"` 渲染：`rows[0]` 当柱高、`rows[1]` 当积水，
  列宽按容器宽度算（320px 下 12 列仍可读），柱高按所有示例的最大值统一缩放，切示例时高度不跳。
- 柱高数字标在柱顶（有积水时标在积水块上方），列下标在基线下；读数（`l / r / maxl / maxr`）仍在右侧。
- 桌面：图表吃满舞台左列（`≥821px` 时左列 1fr），代码卡在右；`≤820px` 单栏，图表在上、读数在下。
- **结果数字的位置**：累计接雨量与已结算列数拼成图表上方的一行标题（两行的 `tag` 合并），
  不进主读数区，避免和 `maxl / maxr` 抢注意力。
- 手机安全区：底部固定条 59px，`body` 预留内距，条上方叠 20px 渐隐。

| 断点 | 行为 |

## 7. 反模式清单（本页不做）

- 不做发光胶囊眉标、渐变描边卡片、左侧彩条装饰。
- 不做卡片套卡片：舞台、代码、读数都在同一层，用 1px 分隔线划分。
- 不做编造的指标。
- 不用 emoji 当图标；图标一律内联 SVG。
- 不用颜色单独承载信息：格子的虚实与数字同时表达状态。
- 不为了「有动效」而给这道题加搬运动效。
- 不自动播放动画。

## 8. 验收口径

- 数据层：`node _tools/lint-model.cjs "42 接雨水 - 双指针"`，error 必须为 0。
- 渲染层：真 Chrome 在 1920 / 1440 / 1280 / 1024 / 390 / 375 / 320 七档截图，检查无横向
  溢出、无遮挡、控制条在视口内。
- 固定底栏：`verify.cjs` 会把每一行滚进视口，断言它能**完整露在固定条上方**（首屏被
  压住不算错，永久看不见才算错）。
- 对比度：见 §2，全部实测。
- 键盘：`←` `→` `空格` `R`；焦点环 `2px solid var(--green)` + `outline-offset: 2px`。底部按键提示用 `<kbd>` 分组，不用「·」串句。
- 未验项写法：任何没有截图佐证的状态，一律写「待人工验收」。
