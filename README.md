# 力扣 · 学习工作区

一题一个文件夹，文件夹名格式：`题号 题目名 - 核心思路`；同思路的题收进专题分组（如 `双指针/`）。每个题目文件夹里固定三种文件：

| 文件 | 作用 |
| --- | --- |
| `README.md` | 题目信息（题面 / 示例 / 提示 / 进阶）、思路推导、手动推演表、最终代码、边界与易错点 |
| `problem.js` | **本题唯一要写的代码**：题面元信息 + 每步状态机（引擎在 `assets/demo.js`） |
| `index.html` | 10 行壳子，双击即可打开，不联网也能跑；永远不用改 |
| `DESIGN.md` | 演示页的设计契约：色板与实测对比度、字号阶梯、动效参数、断点、反模式清单 |

**动手前先读 [`AGENTS.md`](AGENTS.md)** —— 那里写了目录约定、新题流程、演示页规范、已知的坑和验证命令。

## 工具

| 命令 | 作用 |
| --- | --- |
| `node _tools/lint-model.cjs "<题目文件夹>"` | 帧模型校验：跑一遍每个示例，查帧数 / 代码行号 / 索引 / 色调 / 指针，打开页面前先跑 |
| `node _tools/verify.cjs "<题目文件夹>"` | 一次跑完 7 档断点，断言无溢出 / 无小触点 / 无裁切 / 无报错，并输出截图与 report.json |
| `cp -r _template "<NN 题目名 - 思路>"` | 开新题：只改 `problem.js`，前端不用动 |
| `node _tools/contrast.mjs "<题目文件夹>"` | 读 DESIGN.md 里登记的色对，做 WCAG 对比度自检 |

## 通用 Skill

这套做法已经抽成一份可复用的 Skill，放在 [`skill/`](skill/)：

| 文件 | 内容 |
| --- | --- |
| [`skill/SKILL.md`](skill/SKILL.md) | 触发语、三层结构（引擎 / 数据 / 校验）、数据契约、**帧质量六原则**、反模式 |
| [`skill/references/step-model.md`](skill/references/step-model.md) | 帧模型规范：字段表、四种布局（sequence / network / matrix / bars）、叙事写法、二分查找完整示例 |

拿去做别的算法（不限力扣）：抄 `_template/` + 按 step-model 写 `problem.js` + 跑 `lint-model.cjs`，三步就能出一个能点着看的演示页。

## 新增一题

1. 复制模板：`_template/` → `<NN 题目名 - 思路>/`。
2. 按 [`AGENTS.md`](AGENTS.md) §3 的六步走。
3. 跑两条验证命令，全绿后回本文件补一行索引。

## 约定

- 演示页只用静态文件，不引入构建链；任何题目都能单独打开。
- 题目放在专题分组下时，`index.html` 引用共享资源写 `../../assets/`；直接放根目录时写 `../assets/`。
- 演示页里出现的每个十六进制色值都必须在对应 `DESIGN.md` 里登记并附实测对比度。
- 代码面板与题面代码保持等价；若为排版折行，需在面板上注明「为阅读换行，逻辑未改」。
- 共享资源放 `assets/`（目前只有 motion 14.9.1 的 UMD 构建）。
