# DESIGN.md — 对称二叉树 · 演示页

> 色板沿用工作区模板（力扣浅色：白底 + 发丝线 + 黑灰黄），语义色只改指向本题含义。
> 模板来源与取舍理由见 §1 与根目录 `AGENTS.md`。

## 1. 为什么这套方向

这页的主体是一张**树的结构图**，而不是一串数字。视觉重心必须是节点与连线，界面越安静越好。
沿用工作区的力扣浅色骨架：白底 + 发丝线 + 黑灰文字 + 橙色进度条，与官方题解并排看不刺眼。

本题是工作区**第一个 `layout: "network"`** 的演示页——引擎里 `nodes` / `edges` 的渲染分支
就是在这里落地的（见 §5c）。

## 3. 字体

- 正文：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans SC", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif`
- 代码与数字：`"Cascadia Mono", "Cascadia Code", "JetBrains Mono", Consolas, "SF Mono", monospace`

节点数字用等宽字体并居中（`text-anchor: middle` + `dominant-baseline: central`），
字号由引擎按半径算 `round(r * 0.86)`，所以 16–22px 的半径对应 14–19px 的字号，不会溢出圆。

## 4. 尺寸与间距

| 项 | 值 |
| --- | --- |
| 节点半径 | 容器宽 < 340px 时 16，< 460px 时 19，否则 22 |
| 节点命中区 | 直径 ≥ 32px（`verify.cjs` 不把它算触点，纯展示元素） |
| 层间距 | 由 `y` 百分比映射到容器高度，3 层树约占 260px |
| 同心距 | 引擎校验器会警告 < 9%（本页最小层间距约 22%） |
| 触点 | 所有按钮 ≥ 44×44 |

SVG 的 `viewBox` **直接等于像素宽高**，所以半径和字号不随容器缩放——手机上节点不会缩成芝麻。

## 5. 动效

| 项 | 值 |
| --- | --- |
| 时长 | UI 反馈 160ms |
| 缓动 | `cubic-bezier(0.22, 0.9, 0.3, 1)` |
| 降级 | `prefers-reduced-motion: reduce` 时全部 0ms 直切 |

本题**不使用搬运动效**：树上的比较没有「把一个值搬到另一处」的动作。状态变化由三件事承载：
节点外圈变色、连线的虚实、读数区的变化量小墨牌。

## 5b. 状态编码（与图例严格一一对应）

| 画面状态 | 编码 | 图例 |
| --- | --- | --- |
| 已判定相等 | 绿圈 + 浅绿填充 + 绿字 | 已对上 |
| 本步正在比较 | 2.5px 墨圈 + 墨字 | 本步比较 |
| 判定失败 | 虚线圈（4/3）+ 灰字 + 灰底 | 不匹配 / 空位 |
| 空位（`∅`） | 虚线圈（3/3）+ 灰字 + 不填充 | 不匹配 / 空位 |
| 未涉及 | 默认白底 + `--line-strong` 细圈 | 不占图例 |

图例 3 项，正好覆盖三种可辨认状态。**失败用形状（虚线）而不是颜色**——色板里没有危险色，
硬造一个红色会破坏「黑灰黄 + 一个语义色」的克制。

**连线**同理：默认细灰线；比较中的路径不额外染色（节点已经够了）；失败支路的连线转虚线；
空位到父节点的连线从一开始就是虚线。

## 5c. 版面结构

- 一张卡装完主要信息：示例 tab → 图例 → **节点图（SVG）** → 读数 → **解说卡** → 进度条 → 重置与速度。
- **`network` 布局由 `assets/demo.js` 渲染**：顶层或示例级给 `nodes`（`id / label / x / y`，可选
  `ghost`）与 `edges`（`from / to`，可选 `ghost`），坐标是 0–100 的百分比，引擎换算成像素并
  按容器宽度重建 viewBox。
- **树越宽越好读**：`≥821px` 时 `.layout-network .arrays` 收成单列，节点图吃满整行，
  读数落到图下方（`max-width: 460px` 的一行四格），而不是像 `bars` 那样留在右侧窄栏。
- **纵向不留白**：引擎按节点实际用到的 `y` 范围重映射，3 层树的高度约为容器宽的 0.42 倍，
  图下方不再挂一大片空 SVG。
- **空位只在真的被比较时才画**：示例 1 的叶子没有孩子，画 8 个 `∅` 只会添乱，所以不画；
  示例 2 的失败点恰恰是「左边空、右边有值」，那时 `∅` 必须出现，否则观众看不到失败在哪。
- 手机安全区：底部固定条 59px，`body` 预留内距，条上方叠 20px 渐隐。

## 6. 断点

| 断点 | 行为 |
| --- | --- |
| ≥ 1151px | 两栏：舞台（左）+ 代码（右），两卡等高 |
| 821–1150px | 舞台单列、节点图吃满整行；整页收窄到 760px 居中 |
| ≤ 820px | 单栏，读数在图下方 |
| ≤ 700px | 单栏 + 底部固定三段步进 |
| ≤ 380px | 节点半径 16px，字号 14px |

## 7. 反模式清单（本页不做）

- 不做发光胶囊眉标、渐变描边卡片、左侧彩条装饰。
- 不做卡片套卡片：舞台、代码、读数都在同一层，用 1px 分隔线划分。
- 不用 emoji 当图标；空位用 `∅` 字符，不用图片。
- 不用颜色单独承载信息：失败一定有虚线，空位一定有虚线。
- 不给这道题加搬运动效。
- 不自动播放动画。
- 不给 `network` 做自动布局（力/层级算法）——坐标由题目手算，可控且可读。

## 8. 验收口径

- 数据层：`node _tools/lint-model.cjs "树/101 对称二叉树 - 递归镜像"`，error 必须为 0。
- 渲染层：真 Chrome 在 1920 / 1440 / 1280 / 1024 / 390 / 375 / 320 七档截图。
- 固定底栏：`verify.cjs` 会把每一行滚进视口，断言能完整露在固定条上方（首屏被压住不算错）。
- 对比度：见 §2，全部实测。
- 键盘：`←` `→` `空格` `R`；焦点环 `2px solid var(--green)` + `outline-offset: 2px`。
