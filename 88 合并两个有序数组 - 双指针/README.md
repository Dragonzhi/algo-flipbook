# 88. 合并两个有序数组

| 项 | 内容 |

| 来源 | [leetcode.cn/problems/merge-sorted-array](https://leetcode.cn/problems/merge-sorted-array) |

| 时间 / 空间 | `O(m + n)` / `O(1)` |
| 记录时间 | 2026-11-05 |

## 1. 题意

给你两个按**非递减顺序**排列的整数数组 `nums1` 和 `nums2`，另有两个整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中的元素数目。

请你**合并** `nums2` 到 `nums1` 中，使合并后的数组同样按**非递减顺序**排列。

**注意：**最终合并后的数组不应由函数返回，而是存储在数组 `nums1` 中。为了应对这种情况，`nums1` 的初始长度为 `m + n`，其中前 `m` 个元素表示应合并的元素，后 `n` 个元素为 `0`，应忽略。`nums2` 的长度为 `n`。

### 示例

**示例 1**

```
输入：nums1 = [1,2,3,0,0,0], m = 3
     nums2 = [2,5,6],         n = 3
输出：[1,2,2,3,5,6]
解释：需要合并 [1,2,3] 和 [2,5,6]，结果是 [1,2,2,3,5,6]，
     其中加粗的 1、2、3 为 nums1 中的元素。
```

**示例 2**

```
输入：nums1 = [1], m = 1
     nums2 = [],  n = 0
输出：[1]
```

**示例 3**

```
输入：nums1 = [0], m = 0
     nums2 = [1], n = 1
输出：[1]
解释：m = 0，nums1 中没有元素，那个 0 只是占位。
```

### 提示

- `nums1.length == m + n`
- `nums2.length == n`
- `0 <= m, n <= 200`
- `1 <= m + n <= 200`
- `-10^9 <= nums1[i], nums2[j] <= 10^9`

### 进阶

你可以设计实现一个时间复杂度为 `O(m + n)` 的算法解决此问题吗？

## 2. 思路：反向双指针

正向合并的坑在于：`nums1` 前面是被保护的数据，往前面写会覆盖还没处理的元素，于是要么另开数组（`O(m+n)` 空间），要么写完之后整体搬移（多一次 `O(m+n)`）。

反向看就全是好处：**`nums1` 最后 `n` 个位置天然是空的**。合并后最大值一定来自两个数组的末尾之一，那么从 `nums1` 的最后一位往前填，每次只在空位上写数，永远不会覆盖未处理的数据。

- `p1 = m - 1`：`nums1` 有效段的尾。
- `p2 = n - 1`：`nums2` 的尾。
- `tail = m + n - 1`：写入位置。
- 每轮取 `nums1[p1]` 与 `nums2[p2]` 中**较大**的一个，写到 `nums1[tail]`，两个指针各自左移。
- 循环条件用 `p1 >= 0 || p2 >= 0`：任一数组没走完就继续。
- 当一侧耗尽（`p1 == -1` 或 `p2 == -1`），另一侧剩下的元素**直接搬**即可——剩下的那段本身就是有序的，而且已经在 `nums1` 里（`p2 == -1` 时甚至什么都不用做）。

等号的处理：`nums1[p1] > nums2[p2]` 才取 `nums1`，相等时取 `nums2`。这样 `nums2` 中相等的元素排在 `nums1` 相等元素的后面，合并保持稳定。

## 3. 手动推演（示例 1）

`nums1 = [1,2,3,0,0,0]`，`nums2 = [2,5,6]`，初始 `p1 = 2, p2 = 2, tail = 5`。

| 步 | 比较 | 取 | 写入后 nums1 | p1 | p2 | tail |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `3` vs `6` | 6（nums2） | `[1,2,3,0,0,6]` | 2 | 1 | 4 |
| 2 | `3` vs `5` | 5（nums2） | `[1,2,3,0,5,6]` | 2 | 0 | 3 |
| 3 | `3` vs `2` | 3（nums1） | `[1,2,3,3,5,6]` | 1 | 0 | 2 |
| 4 | `2` vs `2` | 2（nums2，相等取 nums2） | `[1,2,2,3,5,6]` | 1 | -1 | 1 |
| 5 | `p2 == -1` | 2（nums1 原地） | `[1,2,2,3,5,6]` | 0 | -1 | 0 |
| 6 | `p2 == -1` | 1（nums1 原地） | `[1,2,2,3,5,6]` | -1 | -1 | -1 |

第 5、6 步是“另一侧已空”的分支：值本来就写在自己位置上，看起来没变化，但指针照常推进——这正是代码里 `p2 == -1` 分支的作用。

## 4. 代码

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int p1 = m - 1, p2 = n - 1;
        int tail = m + n - 1;
        int cur;
        while (p1 >= 0 || p2 >= 0) {
            if (p1 == -1) {
                cur = nums2[p2--];
            } else if (p2 == -1) {
                cur = nums1[p1--];
            } else if (nums1[p1] > nums2[p2]) {
                cur = nums1[p1--];
            } else {
                cur = nums2[p2--];
            }
            nums1[tail--] = cur;
        }
    }
};
```

## 5. 边界与易错点

1. **`m = 0`**：`p1 = -1` 直接走第一个分支，把 `nums2` 全部搬进 `nums1`。
2. **`n = 0`**：`p2 = -1` 走第二个分支，把 `nums1` 原地“写回”，结果不变（也可以提前 `return`）。
3. **循环条件**必须是 `||` 而不是 `&&`，否则一侧耗尽就提前退出，剩下的元素没搬完。
4. **`p1 == -1` 的判断要在 `nums1[p1]` 访问之前**：短路求值的顺序不能反，否则越界读 `nums1[-1]`。
5. **尾部那 `n` 个 `0` 是占位**，不是数据，不能当成真实元素参与比较。
6. **不使用额外空间**是这个解法的考点，别用 `vector<int> merged` 再拷回去。
