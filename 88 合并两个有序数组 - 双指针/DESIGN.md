# DESIGN.md — 合并两个有序数组 · 演示页

> 力扣浅色（黑 / 灰 / 黄）：令牌取自 leetcode.cn 线上 CSS 变量与 `--brand-orange`，语义色按 WCAG 降档。取舍与理由见 §1。

## 1. 为什么这套方向

演示页要在一屏里同时容纳数组舞台、指针、变量表和代码高亮。方向定成**力扣（leetcode.cn）题解页的骨架**：
白底 + 发丝线 + 深灰文字 + 单一橙色强调，信息密度高，不要装饰。

选择理由：这页是刷题笔记里的插图，长期和 leetcode.cn 并排看——浅色页面并排不刺眼，截图贴进笔记也和
官方题解同源。橙色只表示「可交互 / 当前焦点」，取代了深色版里「绿 = 已就位」的装饰性用法。

`--design-system`（query: *algorithm learning tool code visualizer light editorial*）返回的仍是
Dark Mode (OLED) + landing page 版式，与「浅色、单页工具」冲突，**不采用**。令牌直接取自 leetcode.cn
线上 CSS 变量（light-gray / light-green / light-blue / light-purple 色阶）与 --brand-orange，再按
WCAG 降档到可用的文字色。

## 2. 色板（全部登记，新代码不得新增十六进制）

| 角色 | Token | 值 | 实测对比度 |
| --- | --- | --- | --- |
| 页面底色 | `--bg` | `#FFFFFF` | — |
| 卡片 / 面板 | `--panel` | `#FFFFFF` | — |
| 内凹面（读数格、解说、速度分段器、代码区） | `--well` / `--code-bg` | `#F5F5F5` / `#FAFAFA` | — |
| 进度条轨道 | `--well-2` | `#F0F0F0` | 装饰性 |

| 控件描边 | `--line-strong` | `#B7B7B7` | 装饰性 |
| 橙：品牌 / 学习进度（进度条、中等难度） | `--amber` | `#FFA116` | 填充色，不做小字 |
| 橙浅底 | `--amber-soft` | `#FFF7E0` | 只给「中等」难度徽标 |

| 难度徽标：困难 | `.chip-diff[data-diff="困难"]` | `#A1121B` on `#FFECE8` | 7.6:1 |

测量方式：WCAG 相对亮度公式逐对计算（sRGB → 线性化 → (L1+0.05)/(L2+0.05)），不是估值。

**力扣的品牌色不能直接当文字色**：`#01B328` → 2.81:1、`#1CB8B8` → 2.44:1、`#FFB800` → 1.73:1、
`#FFA116` → 2.03:1，都不达 4.5:1。所以语义色一律取同色阶 `-80` 深档；橙只做填充（按钮、进度、
tab 下划线、当前行），不做小字。

**语义分工**：绿 = 主操作（播放）；橙 = 品牌与学习进度（进度条、中等难度）；A / B 只出现在数据上。
「正在执行」不用彩色：代码当前行是**中性灰底 + 2px 墨线**，本步写入的格子是**2px 墨色描边**，
变化过的读数在左侧压一条墨线。黄色一旦用来标状态，就会被读成警告。

## 3. 字体

- 正文：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans SC", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif`
- 代码与数字：`"Cascadia Mono", "Cascadia Code", "JetBrains Mono", Consolas, "SF Mono", monospace`

**降级说明**：不引入 webfont（离线单页），全部走系统栈。Windows 上 Segoe UI Variable（拉丁）
+ Noto Sans SC（中文）已经足够稳；等宽用 Cascadia **Mono** 而不是 Cascadia Code——后者会把
`>=` 渲染成 `≥` 连字，在代码演示里是误读源。字体缺失按栈回退，不出现方框。

字阶：11 / 12 / 13 / 13.5 / 15 / 17 / 20 / 28（px）；正文行高 1.62，代码行高 1.72；
数字统一 `font-variant-numeric: tabular-nums`，步进时宽度不跳。

## 5. 动效三件套

| 项 | 值 |
| --- | --- |
| 时长 | UI 反馈 160ms；指针移动 240ms；数值搬运 320ms |
| 缓动 | `cubic-bezier(0.22, 0.9, 0.3, 1)` |
| 库 | motion（motion.dev 14.9.1，UMD 本地内置 `../assets/motion.min.js`，离线可用）；文件缺失时自动回退到 Web Animations API |
| 降级 | `prefers-reduced-motion: reduce` 时全部改为 0ms 直切，**信息不丢**：数值、指针位置、当前分支、步骤文字照常更新 |

动效必须承载信息：飞行的小块说明「这个值从哪搬到哪」；指针滑动说明「指针真的在动」。没有纯装饰的循环动画。

## 5b. 状态编码（与图例严格一一对应）

| 画面状态 | 编码 | 图例 |
| --- | --- | --- |
| 值来自 nums1 | 格内数字绿色 | 值来自 nums1 |
| 值来自 nums2 | 格内数字蓝色 | 值来自 nums2 |
| 本步写入 | 墨色 2px 描边（中性，不与来源色冲突） | 本步写入 |
| 尚未填充的占位格 | 虚线圈 + `--fg-muted` 数字 | 不占图例（形状本身可读） |
| 已取完 | 整格 42% 透明度 | 不占图例（灰度本身可读） |

图例只保留 3 项（两色与墨框），空位与已取完交给格子自身的虚线/灰度表达，避免手机上折成三行。
指针徽标（p1 绿 / p2 蓝 / tail 灰）自带文字标签，不占图例条目。
行号只在一处出现：解说框右上角的引用；代码卡底部只保留两枚复杂度 chip。

## 5c. 版面结构（多轮盲审后定稿）

- **一张卡装完主要信息**：图例 → 数组格子 → p1/p2/tail/cur 读数与当前分支 → 解说 → 代码当前行小窗 → 进度条 → 重置与速度。读数紧挨它描述的格子，不再分居两栏。
- 桌面：左卡（舞台）右卡（代码），两卡底边等高（`align-items: stretch`）。
- ≤1150px：读数从右侧换到数组下方一行四格，避免和 nums1 末几格相撞。
- ≤700px：单栏，舞台 → 代码；「上一步 / 播放 / 下一步」固定在视口底部（59px 高，`body` 预留 72px 内边距，不压内容），重置与速度留在卡内；触屏不显示键盘快捷键，改为手势提示。
- **手机安全区**：底部固定条高 59px，`body` 预留 96px，条上方叠 20px 渐隐，滚到底时速度组与代码信息条完整可见。
- 指针徽标统一 `min-width: 42px` 居中，格子上下各留 30px（徽标 20px + 指向短线 6px + 4px 呼吸），避免徽标压住格子边框。
- 进度条是**有轨道的真实进度**（4px，`--well` 轨道 + `--green` 填充），数值与右上角「k / n 步」同源。

## 6. 断点

| 断点 | 行为 |
| --- | --- |
| ≥ 1151px | 两栏：舞台（左，数组 + 右侧读数）+ 代码（右），两卡等高，代码卡底部有「本步执行 / 复杂度」信息条 |
| 821–1150px | 单栏且整页收窄到 760px 居中（读数仍在数组右侧），代码在下方，避免代码卡被拉伸出一屏高 |
| ≤ 820px | 读数降为数组下方一行四格 |
| ≤ 700px | 单栏 + 底部固定三段步进 + 代码当前行小窗 |
| ≤ 700px | 格位 40px，读数一行四格，解说改为上下两段（行号独占一行）；底部固定三段步进；出现代码当前行小窗 |
| ≤ 460px | 步进三键按 1 : 1.28 : 1 分配，播放最宽 |
| ≤ 380px | 格位 34px、代码 10.5px，保证 6 格不撑破面板 |

## 7. 反模式清单（本页不做）

- 不做发光胶囊眉标、渐变描边卡片、左侧彩条装饰。
- 不做卡片套卡片：舞台、代码、变量都在同一层，用 1px 分隔线划分。
- 不做编造的指标（“效率提升 300%”之类）。
- 不用 emoji 当图标；图标一律内联 SVG。
- 不用颜色单独承载信息：每格同时有边框样式与图例文字。
- 不自动播放动画（减少动效环境下更不自动播）。

## 8. 验收口径

- 通过方式：真 Chrome（CDP/无头）在 1440 / 1280 / 390 / 375 四档截图，检查无横向溢出、无遮挡、控制条在视口内。
- 对比度：见 §2，全部实测。
- 键盘：`←` `→` 上/下一步，`空格` 播放/暂停，`R` 重置；焦点环 `2px solid var(--amber)` + `outline-offset: 2px`。
- 未验项写法：任何没有截图佐证的状态，一律写「待人工验收」，不写「已验证」。
