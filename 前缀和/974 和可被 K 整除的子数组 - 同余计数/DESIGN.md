# DESIGN.md — 974 · 演示页

> 力扣浅色（黑 / 灰 / 黄）：令牌取自 leetcode.cn 线上 CSS 变量与 `--brand-orange`，语义色按 WCAG 降档。取舍与理由见 §1。

## 1. 为什么这套方向

演示页要在一屏里同时容纳三行数组、读数表和代码高亮。方向定成**力扣（leetcode.cn）题解页的骨架**：
白底 + 发丝线 + 深灰文字 + 单一橙色强调，信息密度高，不要装饰。

选择理由：这页是刷题笔记里的插图，长期和 leetcode.cn 并排看——浅色页面并排不刺眼，截图贴进笔记也和
官方题解同源。橙色只表示「可交互 / 当前焦点」，取代了深色版里「绿 = 已就位」的装饰性用法。

`--design-system`（query: *algorithm learning tool code visualizer light editorial*）返回的仍是
Dark Mode (OLED) + landing page 版式，与「浅色、单页工具」冲突，**不采用**。令牌直接取自 leetcode.cn
线上 CSS 变量（light-gray / light-green / light-blue / light-purple 色阶）与 --brand-orange，再按
WCAG 降档到可用的文字色。

本题的核心是「同余」：三行格子必须**逐列对齐**（`nums[i]` / `pre[i]` / `pre[i] % k`），
观众才能一眼看出哪几个前缀落在了同一个余数上。因此舞台比双指针题多一行，读数列相应收窄。

| 难度徽标：困难 | `.chip-diff[data-diff="困难"]` | `#A1121B` on `#FFECE8` | 7.6:1 |

测量方式：WCAG 相对亮度公式逐对计算（sRGB → 线性化 → (L1+0.05)/(L2+0.05)），不是估值。

**力扣的品牌色不能直接当文字色**：`#01B328` → 2.81:1、`#1CB8B8` → 2.44:1、`#FFB800` → 1.73:1、
`#FFA116` → 2.03:1，都不达 4.5:1。所以语义色一律取同色阶 `-80` 深档；橙只做填充（按钮、进度、
tab 下划线、当前行），不做小字。

**语义分工**：绿 = 主操作（播放）+ 当前前缀；橙 = 品牌与学习进度（进度条、中等难度）；A / B 只出现在数据上。
「正在执行」不用彩色：代码当前行是**中性灰底 + 2px 墨线**，变化过的读数在左侧压一条墨线。黄色一旦用来标状态，
就会被读成警告。

本题的 A / B 不是「数据来源」，而是**时间关系**：A = 此刻正在处理的前缀，B = 这个余数命中了之前的前缀。
这也是为什么同一格会先绿后蓝——颜色跟着「它现在扮演什么角色」走，而不是跟着元素来源走。

## 3. 字体

- 正文：`"Segoe UI Variable Text", "Segoe UI", "Noto Sans SC", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif`
- 代码与数字：`"Cascadia Mono", "Cascadia Code", "JetBrains Mono", Consolas, "SF Mono", monospace`

**降级说明**：不引入 webfont（离线单页），全部走系统栈。Windows 上 Segoe UI Variable（拉丁）

`>=` 渲染成 `≥` 连字，在代码演示里是误读源。字体缺失按栈回退，不出现方框。

数字统一 `font-variant-numeric: tabular-nums`，步进时宽度不跳。

| 项 | 值 |
| --- | --- |
| 时长 | UI 反馈 160ms；指针移动 240ms |

节奏由三件事承载：格子染上语义色、读数变化时左侧闪墨线、代码行同步高亮。硬加飞行块只会是装饰。

## 5c. 版面结构

- **一张卡装完主要信息**：图例 → 三行格子（nums / 前缀和 / 余数）→ 指针 `i` → 读数（`i / cur / r / count` + 余数桶）→ 分支 → 解说 → 进度条 → 重置与速度。
- **读数只列出现过的余数桶**：`cnt` 在代码里是长度 `k` 的 `vector`，`k` 最大 `10^4`，全部画出来既放不下也读不了。画面上 `cnt[r]` 只在该余数第一次出现后入列，未出现的桶恒为 0，与 `vector<int> cnt(k, 0)` 等价；这一取舍写进 README「动态演示」一节。
- 桶的展示顺序 = 首次出现顺序，新桶只往后追加，读数位置不会在步进中来回跳。
- 桌面：左卡（舞台）右卡（代码），两卡底边等高（`align-items: stretch`）。
- ≤1150px：读数从右侧换到格子下方一行四格，避免三行格子把读数挤到屏幕外。
- ≤700px：单栏，舞台 → 代码；「上一步 / 播放 / 下一步」固定在视口底部（59px 高，`body` 预留 96px 内边距，不压内容），重置与速度留在卡内；触屏不显示键盘快捷键，改为手势提示。
- 指针徽标统一 `min-width: 42px` 居中，格子上下各留 30px，避免徽标压住格子边框。
- 进度条是**有轨道的真实进度**（4px，`--well` 轨道 + `--green` 填充），数值与右上角「k / n 步」同源。

## 7. 反模式清单（本页不做）

- 不做发光胶囊眉标、渐变描边卡片、左侧彩条装饰。
- 不做卡片套卡片：舞台、代码、变量都在同一层，用 1px 分隔线划分。
- 不做编造的指标（“效率提升 300%”之类）。
- 不用 emoji 当图标；图标一律内联 SVG。
- 不用颜色单独承载信息：每格同时有边框样式与图例文字。
- 不自动播放动画（减少动效环境下更不自动播）。
- 不把 `k` 个桶全部铺成格子：`k = 10^4` 时不成立，宁可只列出现过的桶。

## 8. 验收口径

- 通过方式：真 Chrome（CDP/无头）在 1920 / 1440 / 1280 / 1024 / 390 / 375 / 320 七档截图，检查无横向溢出、无遮挡、控制条在视口内。
- 对比度：见 §2，全部实测。
- 键盘：`←` `→` 上/下一步，`空格` 播放/暂停，`R` 重置；焦点环 `2px solid var(--amber)` + `outline-offset: 2px`。
- 未验项写法：任何没有截图佐证的状态，一律写「待人工验收」，不写「已验证」。
